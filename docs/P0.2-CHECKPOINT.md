# Checkpoint P0.2 – v0.12 semantic vertical PoC

**Branch:** `refactor/framework-v012-foundation` · **PR:** [#10](https://github.com/FAIRmorph/fairmorph-engine/pull/10)  
**Reference:** FAIRmorph technical framework v0.12, chapters 09–15 and ADR-007 / ADR-038 / ADR-049–052.  
**Scope:** demonstration of stable architectural contracts, **not production readiness**.

## 1. Implementation checkpoint

- **Technical import vs semantics:** imported source bytes remain immutable; semantic source-field drafts and revisions are independent of the import.
- **Versioned field contract:** `SourceFieldDefinition` documents, `source_field_id`, immutable `revision_id` / SHA-256, semantic status and a documented, explicitly user-confirmed decision.
- **Explicit mapping:** the content-addressed DAG binds each target column to a physical source column, substantive mapping rationale, exact resource/field/revision identities and document hash. The PoC validates this provenance before confirming.
- **No second reviewer:** the responsible user confirms the field definitions and the whole projection. A separate reviewer or four-eyes workflow is not required.
- **One confirmation registry:** SQLite `projection_confirmations` holds the immutable pipeline-hash confirmation and hash-pinned evidence; no separate JSON approval file or internal compatibility alias.
- **Event-centric profile selection:** `SamplingEvent` without taxon, GPS, Transect, Dive or Occurrence; optional explicit `Occurrence` and `MeasurementOrFact`, separate technical vs domain identifiers. No automatic reinterpretation of counts as taxon occurrences.
- **RUN/2 vertical path:** CSV source -> allowlisted Polars DAG -> explicit entity Parquet tables -> configuration/inputs/evidence snapshot, manifest, checksums and RUN verification.
- **PoC tests:** positive end-to-end and event-only paths; rejection of missing field confirmation, incorrect revision pin, duplicate event identity and incomplete target binding.

See [the executable contract](project-driven-run.md). In this PoC, domain tables are **tabular Parquet outputs**; SQLite is the registry and catalog, not a row-by-row mirror.

## 2. Evidence and acceptance

**Status:** Implemented on the PR branch; **not formally accepted until the latest Linux + Windows CI both pass**, including Ruff lint/format and pytest. Automated tests use small synthetic fixtures; they are not a sign-off for scientific data or real user datasets.

P0.2 demonstration acceptance:
1. A resource is imported without semantic interpretation.
2. Every mapped source column has a user-confirmed immutable field revision.
3. A mapping with wrong/unconfirmed field semantics fails before a semantic RUN.
4. A responsible user can confirm the mapping without a separate reviewer.
5. Event-only and Event + Occurrence + Measurement projections run without inferring taxonomy, event coordinates, or presence status.
6. A `MeasurementOrFact.value = 0` remains numeric zero; field nulls are not silently replaced.
7. RUN/2 captures source-object hashes, exact field revisions, confirming-user evidence, configuration hash, output checksums; `verify-project` validates those pins.
8. A CI-green commit and the test matrix are recorded before P0.2 is marked accepted.

## 3. Next work packages – deliberately outside this PoC

| Priority | Package | Target / acceptance boundary |
|---|---|---|
| **P0.2 closeout** | CI and regression acceptance | All Linux/Windows CI jobs green, negative tests and no stale reviewer/approval interfaces; recheck RUN snapshot integrity |

| **P0.7** | Publication adapters | Explicit Event-Core vs Occurrence-Core decision; EML + DwC-A, geo/media and target-profile conformance; no auto-publishing |
| **P0.8** | Independent E2E demonstrations | CS-PHOC numeric regression (16,940 values, 11,599 zeros), a second structurally different survey and negative/missing input cases |
| **Hardening** | Production-grade persistence | SQLite append-only triggers/constraints, migrations, backup/restore, fault injection, large-data/memory tests, canonical JSON standard, schema compatibility policy |

These are **checkpoint work items**, not a claim that each belongs to the minimal P0.2 PoC. They are staged to preserve the framework's future structure while avoiding speculative implementation.

## 4. Explicit non-goals at this checkpoint

No production user/role management; no separate scientific reviewer mandate;
no automatic field interpretation or inferred taxonomic identity;
no complete Workbench; no row-per-entity SQLite persistence;
no general spatial/geometric pipeline; no final DwC-A, EML or publication profile;
no guaranteed production migration compatibility for the draft PR interfaces.

**Decision for continued development:** retain the clean v0.12 registry and mapping structures; extend at the next demonstrable vertical slice rather than implementing all open contract details now.
